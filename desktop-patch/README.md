# Desktop Configuration Companion

A companion to the Canadian Timezone Shim that helps a selected Linux
desktop environment resolve the custom `Canadian/*` timezone identifiers
the core installer creates.

## Why is this separate from the core installer?

The core installer (`install.sh`) owns:

- Generation, atomic installation, validation, tzdata-update rebuild, and
  removal of the custom `Canadian/*` TZif files under
  `/usr/share/zoneinfo/Canadian/`.
- `/etc/localtime`
- System timezone selection

This companion owns only **desktop-environment configuration**. Some
desktops (KDE's digital clock being the clearest example) store an
explicit IANA zone id inside the desktop's own settings rather than
following `/etc/localtime`. When that happens the desktop keeps
resolving `America/Vancouver` against `/usr/share/zoneinfo/America/`
— the untouched official IANA file — and displays `MST` even though
`date` shows `PCT`. The companion utility rewrites that one stored id
from `America/Vancouver` → `Canadian/PCT` so the desktop agrees with
the system.

If the desktop already follows `/etc/localtime`, the utility reports
"no change needed" and writes nothing.

## Architecture

```text
official IANA source   →  Canadian/<ABBR> (custom TZif)   →   /etc/localtime
     (read-only)             (generated by core install.sh)   (repointed by core)

                                                          ↓
                                            desktop stores explicit id?
                                                          ↓
                                          yes → desktop-patch migrates that one id
                                          no  → nothing to do
```

`Canadian/*` is a **custom namespace owned entirely by this project.**
It is not published by IANA. It exists as real TZif files at
`/usr/share/zoneinfo/Canadian/PCT` and similar, so any library that
scans the system zoneinfo directory — Qt, glibc, Python's `zoneinfo` —
resolves them correctly.

## What the desktop utility does / does not do

**Does:**

- Detect the active desktop session.
- Read the specific stored zone identifier inside the user's desktop
  configuration (KConfig section key, GSettings key, Xfconf property,
  LXQt INI plugin key, etc.).
- Rewrite only that identifier to the matching `Canadian/*` custom id.
- Preserve every unrelated setting byte-for-byte in the same file.
- Save the previous value in a per-user restoration manifest.
- Refuse to write anything if the target `Canadian/*` file isn't
  installed (instructs the user to run `install.sh` first).
- Restore the original identifier from the manifest.

**Does not:**

- Generate or modify any TZif file.
- Modify `/etc/localtime`.
- Change the desktop's system timezone selection.
- Write into `/usr/share/zoneinfo/` (that's the core installer's job,
  as root).
- Rewrite anything when the desktop is in `Local` mode.
- Restart a desktop shell, panel, or session (never without explicit
  user confirmation).
- Touch more than one desktop per invocation.
- Ever edit `zone.tab`, `zone1970.tab`, or ICU data.

## Usage

```bash
# Interactive menu
./desktop-patch/desktop-patch.sh

# Configure a specific desktop non-interactively
./desktop-patch/desktop-patch.sh --desktop kde

# Dry run — inspect and show what would change, write nothing
./desktop-patch/desktop-patch.sh --desktop kde --dry-run

# Detect the running desktop and show recommendation (asks before writing)
./desktop-patch/desktop-patch.sh --detect

# Show current status
./desktop-patch/desktop-patch.sh --status

# Restore the previous identifier from the manifest
./desktop-patch/desktop-patch.sh --restore

# Help
./desktop-patch/desktop-patch.sh --help
```

The distribution brand shown in menus (Kubuntu, Linux Mint Cinnamon,
Ubuntu Budgie, etc.) is purely informational. What actually decides the
adapter is the session's `XDG_CURRENT_DESKTOP` / `XDG_SESSION_DESKTOP`
values plus the presence of the corresponding configuration backend.

**What "renders_expected_abbreviation: yes" means in this table.** For
the container-verified rows it means the desktop's own stack resolves
the installed `Canadian/*` identifier to the expected abbreviation
through the mechanism the check uses (glibc TZ lookup, Xfconf
round-trip, INI round-trip). It does not mean a panel widget was
visually observed rendering the abbreviation in a graphical session.
Only `kde` is live verified in that stronger sense.

## Live KDE case: no write needed

In a fresh KDE Plasma session, the digitalclock applet's
`selectedTimeZones` list is set to `Local,Etc/UTC`. Because it uses
`Local`, the clock follows `/etc/localtime` via
`QTimeZone::systemTimeZone()`. Once the core installer has repointed
`/etc/localtime` to `/usr/share/zoneinfo/Canadian/PCT`, the clock shows
`PCT` automatically — no desktop-patch run is required.

The companion utility is only needed when the user has manually
selected a specific zone (`timeZone=Selected` mode in Plasma's UI),
storing an explicit `America/Vancouver`. In that case:

```
desktop-patch --desktop kde
```

rewrites only that one `selectedTimeZones=` line inside the digital
clock's `[Configuration]` section, preserving every other applet
setting byte-for-byte, and records the previous value in a restoration
manifest.

## Restoring

```bash
./desktop-patch/desktop-patch.sh --restore
```

The utility uses the last manifest it wrote. It refuses to overwrite
any value the user changed manually after the patch. If the current
stored id is neither the pre-patch value nor the post-patch value, the
utility warns before doing anything.

## Where state lives

Per-user restoration manifests:

```
~/.local/state/canadian-tz-shim/desktop-patches/
    manifest-<id>.json
    backups/
        kde-<timestamp>/
            plasma-org.kde.plasma.desktop-appletsrc.<timestamp>.bak
```

System-wide custom-zone state (managed by the core installer, **not**
by this companion):

```
/var/lib/canadian-tz-shim/custom-zones.json
```

## Testing

```bash
./desktop-patch/test-desktop-patch.sh
```

Runs 53 checks covering:

- Desktop detection with each supported environment.
- Manual selection overriding detection.
- Missing commands / schemas / keys.
- Missing or malformed config files.
- Multiple KDE clock applets.
- Plasma 5 and Plasma 6 fixtures.
- Dry-run producing no filesystem changes.
- Idempotent re-application.
- Exact preservation of unrelated configuration.
- Failed verification triggering rollback.
- Restoration from a valid manifest.
- Refusal to patch more than one desktop per invocation.
- Refusal to operate as the wrong user.
- Paths containing spaces and unusual-but-valid characters.
- Interrupted writes leaving the original file usable.

Tests run inside a temporary sandbox `$HOME` and never touch the
developer's real Plasma configuration.

## Verification levels per desktop

The companion utility's adapters are verified at different levels
depending on what the developer's environment could exercise. See
[`desktop-patch/docker/README.md`](docker/README.md) for the container
harness details and [`../DESKTOP_COMPANION_IMPLEMENTATION.md`](../DESKTOP_COMPANION_IMPLEMENTATION.md)
for the full evidence trail.

- **KDE Plasma — Live verified.** Ran on a real KDE Plasma 6.8.2
  session. The digital clock uses `Local` mode which follows
  `/etc/localtime`, so once the core installer repoints the symlink
  and registers `Canadian/PCT` in `zone.tab` / `zone1970.tab`, the
  clock shows `PCT` without any configuration change (a one-time
  plasmashell restart is needed because Qt parses the tab file at
  process startup). Where a clock applet stores an explicit IANA
  id, the adapter's narrow `selectedTimeZones=` rewrite was also
  exercised against a realistic fixture.
- **GNOME, Cinnamon, MATE, Budgie — Integration verified.** Real
  distro-packaged schemas driven inside a container. The
  integration result for all four is that **no explicit per-user
  timezone key is exposed on Debian trixie** by the packaged
  settings stack, so the companion correctly performs no write and
  the desktop's clock follows `/etc/localtime`.
- **XFCE — Integration verified.** Real Xfconf D-Bus service inside
  a private container session, driven by the actual
  `xfconf-query` command. The clock plugin's property path and
  name — `/plugins/plugin-<N>/Timezone` (capital T) — are
  discovered correctly and the round-trip works.
- **LXQt — Fixture verified.** The `panel.conf` file format the
  adapter reads and writes is the real LXQt layout (top-level
  widget sections with `type=clock` or `type=worldclock` inside
  the section), and it is the file the shipped `lxqt-panel`
  package writes. Unrelated sections, alignment keys, and every
  other widget's settings survive byte-for-byte. A running panel
  was not visually exercised.

In each container the capability report at the end of the check
includes a `validation_level:` line (`integration` or `fixture`),
plus per-desktop flags for `recognized`, `enumerated`,
`selectable`, and `renders_expected_abbreviation`. The KDE row
carries `live` in the reports this project maintains.
